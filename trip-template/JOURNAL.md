# 旅途手帳：Claude 處理規則

Chang 和老婆旅行時，會在 Claude App 傳照片給 Claude Code，說「記帳」「日記」或「整理今天的日記」。
Claude 依這份規則處理，把結果寫進這趟資料夾的 `journal-data.json`，推上 GitHub。手帳頁（`journal.html`）會讀這個檔案顯示，收據也會自動同步到行程頁的刷卡紀錄。

一律用繁體中文回覆。

## 隱私（repo 是公開的）

- **照片本身絕對不要 commit**，只寫整理後的文字。
- 不寫姓名、電話、地址、卡號末四碼、會員編號、訂位編號、收據上的交易序號。
- 收據只記店名、品項、金額、稅、是否免稅。

## 先判斷是哪一天、幾點

- `day`：D1、D2…對應 `journal.html` 裡 `TRIP.days` 的日期（開新的一趟時把這行改成實際日期，例如 D1=5/1、D2=5/2）。
- 使用者有說就照說的；沒說時，收據看收據上的日期，照片看當下日本時間（UTC+9）。
- `time`：24 小時制 `HH:MM`（當地時間）。收據看收據上的時間，照片用當下時間。

## 「記帳」：收據 → `receipts`

一張收據一筆，追加到 `receipts` 陣列：

```json
{
  "id": "r20261018-1432-matsukiyo",
  "day": "D2",
  "time": "14:32",
  "store": "マツモトキヨシ 心斎橋店",
  "store_zh": "松本清藥妝 心齋橋店",
  "items": [
    {"ja": "ロートVアクティブ", "zh": "樂敦眼藥水", "qty": 2, "price": 1960}
  ],
  "tax": 298,
  "total": 3280,
  "tax_free": false,
  "card": "U",
  "who": "me",
  "notes": "退稅、折扣、點數等重點，沒有就留空"
}
```

- `id`：`r` + 日期 + 時間 + 店名英文簡寫，不能重複。
- `zh` 要說明是什麼商品，不要只音譯（例如「ロートVアクティブ」寫「樂敦眼藥水」）。
- 看不清楚的數字填 `null`，不要猜。折扣列成負數的一行。
- `card`：代號對應 `index.html` 的 `CARDS`（U=uniopen、K=熊本熊卡、KP=PayPay、J=吉鶴 Apple Pay、W=老婆 JCB、CUBE=CUBE、C=現金，依這趟實際用的卡調整）。使用者沒說時：信用卡用 U，現金用 C。
- `who`：`me` 或 `wife`，沒說就 `me`。
- 回覆時列出：店名、品項中文、合計 ¥ 與約 NT$（匯率 4.65），以及記在哪張卡。

## 「日記」：照片 → `moments`

一張照片一筆，追加到 `moments` 陣列：

```json
{
  "id": "m20261018-1015-pokemon",
  "day": "D2",
  "time": "10:15",
  "title": "寶可夢中心 DX 的巨大皮卡丘",
  "summary": "2 到 3 句，像日記，具體描述照片裡看得到的東西和氣氛。",
  "place": "寶可夢中心 DX（大丸心齋橋）",
  "ja": [{"ja": "限定商品", "zh": "限定商品"}],
  "note": "使用者自己說的心得，原話照寫；沒有就留空"
}
```

- 照片裡的日文（招牌、菜單、說明牌）最多 8 條放 `ja`，沒有就 `[]`。只寫看得到的，不要捏造。
- `place` 參考 `index.html` 當天行程推測，不確定就留空。
- 菜單照片：`ja` 翻每道菜，`summary` 寫推薦點什麼。

## 「整理今天的日記」→ `diaries`

- 讀當天所有 `moments` 和 `receipts`，寫一篇 150–250 字的繁體中文旅遊摘要。
- 用「我們」的口吻，依時間順序，只寫紀錄裡有的內容。
- 最後一行「今日關鍵字：」加 3 個詞。
- 存成 `"diaries": {"D2": "全文"}`，同一天重寫就覆蓋。

## 購物清單 → `shopping.json`

使用者說「購物清單加：…」「○○買到了」「清單刪掉○○」時，更新同資料夾的 `shopping.json`：

```json
{"id": "s-rohto-eye", "name": "樂敦眼藥水", "ja": "ロートVアクティブ", "cat": "💊 藥妝", "where": "Sugi、松本清、唐吉訶德", "price": "約¥1,000", "qty": 2, "for": "送媽媽", "note": "", "bought": false}
```

- `name` 中文名、`ja` 在店裡找得到的日文名（給店員看用），不確定日文名就留空，不要編。
- `cat`：**依東西本身是什麼來分類**，不是依店家。每類前面加一個 emoji，名稱 2–5 個字。常用的有：💊 藥品、💄 美妝保養、🍫 零食甜點、🎁 伴手禮、🍶 酒飲、🃏 寶可夢、🧸 玩具扭蛋、👕 服飾、👟 鞋包、🔌 電器、✏️ 文具、🏠 生活雜貨、🍜 食材調味。
  - 清單裡沒有適合的類別就新開一類；已經有的類別一定沿用同一個名稱和 emoji（不要同時出現「零食」和「零食甜點」）。
  - 同一類超過 10 項可以再細分（例如「💊 藥品」拆成「👁️ 眼藥」「🤕 痠痛貼布」）；只有 1 項的小類別，能併到相近的類別就併。
  - 每次加東西後重新檢查整份清單的分類是否一致，順序依類別排好（同類放在一起）。
- `where` 寫這趟行程上順路、買得到的店；`price` 只寫大概價位，不確定就留空。
- 「○○買到了」→ 把那一項 `bought` 改成 `true`；「記帳」時如果收據上有清單裡的東西，也順便改成 `true`，回覆時說勾掉了哪幾項。
- 清單顯示在網站的「🛒 清單」分頁（`shopping.html`）。網頁上的打勾只存在那支手機；Claude 改 `bought` 才會兩支手機都看到。
- 寫完一樣更新 `updated`、驗證 JSON、commit、push。

## 修改與刪除

使用者說「那筆改刷熊本熊」「刪掉剛剛那張」時，找到對應的 `id` 直接改或刪，回覆時說改了哪一筆。

## 寫完之後

1. 把 `updated` 改成現在的當地時間，例如 `"10/18 14:40"`。
2. 驗證 JSON（改了哪個檔就驗哪個）：`python3 -m json.tool <這趟資料夾>/journal-data.json > /dev/null`
3. 照 repo 慣例 commit，訊息例如「手帳：D2 松本清收據」，然後推上去：
   `git fetch -q origin main && git rebase -q origin/main && git push -q origin HEAD:main`
4. 回覆整理結果，提醒在手帳頁按「☁️ 怎麼交給 Claude？→ 🔄 重新整理」就會看到。
