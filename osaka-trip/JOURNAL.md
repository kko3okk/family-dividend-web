# 旅途手帳：Claude 處理規則

Chang 和老婆在大阪旅行（2026/10/17–10/24）時，會在 Claude App 傳照片給 Claude Code，說「記帳」「日記」或「整理今天的日記」。
Claude 依這份規則處理，把結果寫進 `osaka-trip/journal-data.json`，推上 GitHub。手帳頁（`journal.html`）會讀這個檔案顯示，收據也會自動同步到行程頁的刷卡紀錄。

一律用繁體中文回覆。

## 隱私（repo 是公開的）

- **照片本身絕對不要 commit**，只寫整理後的文字。
- 不寫姓名、電話、地址、卡號末四碼、會員編號、訂位編號、收據上的交易序號。
- 收據只記店名、品項、金額、稅、是否免稅。

## 先判斷是哪一天、幾點

- `day`：D1=10/17、D2=10/18、D3=10/19、D4=10/20、D5=10/21、D6=10/22、D7=10/23、D8=10/24。
- 使用者有說就照說的；沒說時，收據看收據上的日期，照片看當下日本時間（UTC+9）。
- `time`：24 小時制 `HH:MM`（日本時間）。收據看收據上的時間，照片用當下時間。

## 「記帳」：收據 → `receipts`

一張收據一筆，追加到 `receipts` 陣列：

```json
{
  "id": "r20261018-1432-matsukiyo",
  "day": "D2",
  "time": "14:32",
  "store": "マツモトキヨシ 心斎橋店",
  "store_zh": "松本清藥妝 心齋橋店",
  "items": [
    {"ja": "ロートVアクティブ", "zh": "樂敦眼藥水", "qty": 2, "price": 1960}
  ],
  "tax": 298,
  "total": 3280,
  "tax_free": false,
  "card": "U",
  "who": "me",
  "cat": "shop",
  "notes": "退稅、折扣、點數等重點，沒有就留空"
}
```

- `id`：`r` + 日期 + 時間 + 店名英文簡寫，不能重複。
- `zh` 要說明是什麼商品，不要只音譯（例如「ロートVアクティブ」寫「樂敦眼藥水」）。
- 看不清楚的數字填 `null`，不要猜。折扣列成負數的一行。
- `card`：U=uniopen、K=熊本熊卡、KP=玉山Wallet PayPay、J=吉鶴 Apple Pay、W=老婆 JCB、CUBE=CUBE、S=西瓜卡 Suica、C=現金。使用者沒說時：收據寫クレジット就用 U，現金用 C，PayPay 用 KP；USJ 園內用 W（老婆）或 K。
- `who`：`me` 或 `wife`，沒說就 `me`。
- `cat`：分類，手帳「購物收據」的篩選用。food=餐飲（餐廳、咖啡、小吃）、conv=超商超市（便利商店、超市、販賣機）、shop=購物（藥妝、服飾、雜貨、周邊）、play=遊樂扭蛋（扭蛋、夾娃娃、遊樂場、一番賞）、trans=交通、stay=住宿（含住宿稅）、sight=景點門票（神社、展望台、入場券）、other=其他。沒寫的話網頁會依店名猜。
- `group`／`group_name`：同一家店分好幾次付款（不同卡、不同人刷）時，每次付款各記一筆收據，再給它們相同的 `group`（例如 `d5-crossstore`）和合併後的店名 `group_name`。手帳列表會合併成一張，列出每次付款；刷卡紀錄、西瓜卡稽核、我／老婆篩選仍照每一筆算。
- `suica`：西瓜卡（`card` 是 S）才寫，標是哪一張：A＝我的消費用（…3112）、B＝我的搭車用、W＝老婆的（…3216）。新的一趟依實際卡片調整 `journal-data.json` 的 `suica.cards`。
- 照片：使用者要「附上圖片」時，把照片壓到長邊 1600px 放進**私有庫** `family-dividend-data/trips/<趟>/journal/<moment id>.jpg`（用 git push，不要放公開庫），在那筆 `moments` 加 `"pimg": "trips/<趟>/journal/<id>.jpg"`。手帳只有驗證過的手機會顯示照片，訪客看不到。
- 收據或錢包截圖上看得到西瓜卡**餘額**時，在 `suica.anchors` 加一筆 `{"c":"A","day":"D5","time":"15:26","bal":15739,"src":"7-11 收據"}`（時間＝那筆消費之後）。手帳「購物收據」上方的「🚃 西瓜卡餘額稽核」會用最後一筆餘額往下扣，對不上就是漏記。
- 回覆時列出：店名、品項中文、合計 ¥ 與約 NT$（匯率 4.65），以及記在哪張卡。

## 「日記」：照片 → `moments`

一張照片一筆，追加到 `moments` 陣列：

```json
{
  "id": "m20261018-1015-pokemon",
  "day": "D2",
  "time": "10:15",
  "title": "寶可夢中心 DX 的巨大皮卡丘",
  "summary": "2 到 3 句，像日記，具體描述照片裡看得到的東西和氣氛。",
  "place": "寶可夢中心 DX（大丸心齋橋）",
  "ja": [{"ja": "限定商品", "zh": "限定商品"}],
  "note": "使用者自己說的心得，原話照寫；沒有就留空"
}
```

- 照片裡的日文（招牌、菜單、說明牌）最多 8 條放 `ja`，沒有就 `[]`。只寫看得到的，不要捏造。
- `place` 參考 `index.html` 當天行程推測，不確定就留空。
- 菜單照片：`ja` 翻每道菜，`summary` 寫推薦點什麼。

## 「整理今天的日記」→ `diaries`

- 讀當天所有 `moments` 和 `receipts`，寫一篇 150–250 字的繁體中文旅遊摘要。
- 用「我們」的口吻，依時間順序，只寫紀錄裡有的內容。
- 最後一行「今日關鍵字：」加 3 個詞。
- 存成 `"diaries": {"D2": "全文"}`，同一天重寫就覆蓋。

## 購物清單 → `shopping.json`

使用者說「購物清單加：…」「○○買到了」「清單刪掉○○」時，更新同資料夾的 `shopping.json`：

```json
{"id": "s-rohto-eye", "name": "樂敦眼藥水", "ja": "ロートVアクティブ", "cat": "💊 藥妝", "where": "Sugi、松本清、唐吉訶德", "price": "約¥1,000", "qty": 2, "for": "送媽媽", "note": "", "bought": false}
```

- `name` 中文名、`ja` 在店裡找得到的日文名（給店員看用），不確定日文名就留空，不要編。
- `cat`：**依東西本身是什麼來分類**，不是依店家。每類前面加一個 emoji，名稱 2–5 個字。常用的有：💊 藥品、💄 美妝保養、🍫 零食甜點、🎁 伴手禮、🍶 酒飲、🃏 寶可夢、🧸 玩具扭蛋、👕 服飾、👟 鞋包、🔌 電器、✏️ 文具、🏠 生活雜貨、🍜 食材調味。
  - 清單裡沒有適合的類別就新開一類；已經有的類別一定沿用同一個名稱和 emoji（不要同時出現「零食」和「零食甜點」）。
  - 同一類超過 10 項可以再細分（例如「💊 藥品」拆成「👁️ 眼藥」「🤕 痠痛貼布」）；只有 1 項的小類別，能併到相近的類別就併。
  - 每次加東西後重新檢查整份清單的分類是否一致，順序依類別排好（同類放在一起）。
- `at`：這樣東西排在行程的哪裡買，填行程項目的錨點陣列（例 `["D5-drug","D7-sbs"]`）。行程頁那一項下面會自動列出「🛒 清單：這裡可以買」，已買的劃掉。新增東西時一定要填，找不到合適的錨點就在 `index.html` 對應的行程項目加 `data-shop`。目前大阪的錨點：`D1-konbini` D1 晚上便利商店／超市補貨、`D4-lawson` D4 閉園後 CityWalk LAWSON、`D2-poke` 寶可夢中心DX、`D2-gacha` 扭蛋之森、`D5-poke` 大丸梅田13F、`D5-yodo` 友都八喜梅田、`D3-umeda` D6 下午中崎町＋茶屋町（10/19 從 D3 移過去）（含 C-pla、HEP FIVE、阪急梅田 B1、紀伊國屋）、`D5-loft` 梅田 LOFT＋阪神 B1、`D5-drug` 心齋橋藥妝（10/19 起排在 D7 心齋橋筋）、`D7-sbs` 心齋橋筋商店街（含大丸心齋橋周邊）、`D7-donki` 唐吉訶德最後補貨。
- `where` 寫這趟行程上順路、買得到的店；`price` 只寫大概價位，不確定就留空。
- `img`（選填）商品圖片網址：只放官方或商店的圖片連結，不要把圖片檔 commit 進 repo（公開庫）；圖片載不出來網頁會自動隱藏。`url`（選填）官方商品頁。沒圖也沒關係，網頁每一項都有「🔍」可以開大卡片（日文名大字＋「これはありますか？」＋ Google 圖片搜尋）給店員看。
- 「○○買到了」→ 把那一項 `bought` 改成 `true`；「記帳」時如果收據上有清單裡的東西，也順便改成 `true`，回覆時說勾掉了哪幾項。
- 清單顯示在網站的「🛒 清單」分頁（`shopping.html`）。網頁上的打勾會自動同步：驗證過 Token 的手機寫進私有庫 `family-dividend-data/trips/<趟>/shop-ticks.json`（`trip-kit/shopsync.js`），再盡量寫一份公開副本 `<旅程資料夾>/shop-ticks.json` 給分享連結看（Token 要有網站庫寫入權限）。`shop-ticks.json` 不要手改；Claude 改 `bought` 仍然有效，但那一項如果有人在網頁上打過或取消過勾，就以網頁的勾為準。
- 寫完一樣更新 `updated`、驗證 JSON、commit、push。

## 修改與刪除

使用者說「那筆改刷熊本熊」「刪掉剛剛那張」時，找到對應的 `id` 直接改或刪，回覆時說改了哪一筆。

## 寫完之後

1. 把 `updated` 改成現在的日本時間，例如 `"10/18 14:40"`。
2. 驗證 JSON（改了哪個檔就驗哪個）：`python3 -m json.tool osaka-trip/journal-data.json > /dev/null`
3. 照 repo 慣例 commit，訊息例如「手帳：D2 松本清收據」，然後推上去：
   `git fetch -q origin main && git rebase -q origin/main && git push -q origin HEAD:main`
4. 回覆整理結果，提醒在手帳頁按「☁️ 怎麼交給 Claude？→ 🔄 重新整理」就會看到。

## 攜帶物品清單（packing.json）

- 使用者說「行李清單加○○」→ 在 `packing.json` 的 `items` 加一筆（`id` 英文小寫不重複、`name`、`cat` 沿用現有類別、`note` 一句提醒、`qty` 數量可省略），推上 GitHub。
- 打勾由網頁同步（私有庫 `trips/<趟>/pack-ticks.json`），不要手改。

- **消費總結**：刷卡頁最上面的「🧾 旅程消費總結」直接讀 `journal-data.json` 的收據，依「誰付的／用什麼付／消費類型／每天」統計；`card.html` 的 `#spendSum` 要把 `data-end` 設成回程日（YYYY-MM-DD），當天起自動展開；`data-fx` 是粗估匯率。
- **出發前預付**：`journal-data.json` 的 `prepaid` 陣列（id／name／cat／amount／cur＝TWD 或 JPY／note，可選 who／card），刷卡頁消費總結會列出並算「整趟合計（台幣）」。只寫金額和品名，**不要寫訂單編號、姓名、電話、車牌**。
- **旅程結束後**：跑 `python3 trip-kit/tools/build-spend-summary.py <趟的資料夾>` 產生 `spend-summary.json`，刷卡頁就只讀這個小檔、不用下載整份手帳；之後有改帳要重跑一次。
